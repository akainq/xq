The XQ language: a short guide

In XQ everything is immutable, and concurrency works through processes and messages.

#Program

function main(): void {
  console.log("Hello, XQ!");
}

The entry point is main with no parameters. The program ends when main ends: with exit code 0, or 1 if main crashed. If main receives messages, it has this: Process<M> (see Processes).

#Modules

A file is a module. Everything is private unless marked export:

// geometry.xq
export type Point = { x: float; y: float };
export const ORIGIN_X = 0.0;
export function dist(a: Point, b: Point): float {
  return Math.sqrt(sq(a.x - b.x) + sq(a.y - b.y));
}
function sq(v: float): float { return v * v; }   // not visible outside

// main.xq
import { dist, type Point } from "./geometry";   // named import
import { dist as distance } from "./geometry";    // with renaming
import * as geo from "./geometry";               // namespace
const p: geo.Point = { x: 1.0, y: 2.0 };
console.log(geo.dist(p, p), distance(p, p));
  • Paths: "./x", "../dir/x" (the .xq extension is implied, and a directory with an index.xq is a module too); "std/..." is the standard library.
  • Circular imports are allowed: the top level holds only declarations, and the order of initialization does not matter.
  • Functions from modules can be passed as values (xs.map(geo.dist)) and spawned as processes (spawn(mod.server, 0)).

#Values and types

const n: int = 42;              // 64-bit integer; overflow crashes the process
const x = 3.14;                 // float
const ok = true;                // bool
const s = `n = ${n}`;           // string (UTF-8), template strings
const nothing: int | null = null;
const p = { x: 1, y: 2 };       // record { x: int, y: int }
const xs = [1, 2, 3];           // int[]
const pair: [string, int] = ["a", 1];   // tuple
  • int / int is integer division (7 / 2 == 3); mixed arithmetic gives float.
  • Bitwise operators work only on int (64 bits): &, |, ^, ~, and the shifts <<, >> (sign-extending) and >>> (zero-filling). The shift count is taken modulo 64, as in Java and C#. Precedence is as in JavaScript, so a & b === c is a & (b === c), and the compiler rejects that comparison as int & bool.
  • == and === are structural equality: { x: 1 } === { x: 1 } is true.
  • + with a string concatenates and converts the other operand to a string.
  • There are no number, any or undefined types: use int/float, unknown, null.

#Bindings

There is only const. Destructuring works as in JS, but a refutable pattern that does not match crashes the process (badmatch), as in Erlang:

const { x, y } = p;
const [first, ...rest] = xs;
const [a, b] = [1, 2];

#Functions

function add(a: int, b: int): int {
  return a + b;
}

function greet(name: string) {        // the return type is inferred (except for recursive functions)
  return `hi, ${name}`;
}

const inc = (x: int) => x + 1;        // arrow functions and closures
const adder = (a: int) => (b: int) => a + b;

function first<T>(xs: T[]): T | null { // generics
  return match (xs) {
    [] => null,
    [h, ..._] => h,
  };
}

The last expression of a block is its value. A call in tail position is guaranteed not to grow the stack, so recursion replaces loops:

function sumTo(n: int, acc: int): int {
  if (n == 0) return acc;
  return sumTo(n - 1, acc + n);      // 10,000,000 iterations without stack growth
}

For side effects, there are for (const x of xs) { ... } and for (const i of range(0, 10)) { ... }.

Parameters with a default value can be omitted, as in TS:

function connect(host: string, port: int = 8080, options: Options = {}): Result<Conn> { ... }
connect("a"); connect("b", 443); connect("c", 443, { secure: true });

A default value must be a constant: a literal, an expression of literals, a record or an array of them, or a module const. Such parameters come at the end of the list, and only declared functions have them (arrow functions do not).

A /** ... */ comment above a function, type or constant is its documentation, as in TypeScript: the editor shows it on hover together with the signature.

#Records and arrays

Immutable updates:

const q = { ...p, y: 10 };                 // a new record
const ys = [...xs, 4];                     // a new array
const zs = xs.with(0, 100);                // replace an element (ES2023)

An optional field label?: string is the same as label: string | null. In a record literal, a field whose type allows null can be left out: const o: Options = { port: 1 } gives host: null.

Array methods (none of them mutate): length, xs[i], map, filter, reduce, forEach, some, every, find (→ T | null), findIndex, includes, indexOf, join, slice, concat, with, append, toReversed/reverse, toSorted/sort (with or without a comparator). The callbacks of map/filter/... can take (x) or (x, i).

Strings: length (in characters), s[i], slice, substring, includes, startsWith, endsWith, indexOf, lastIndexOf (with a position argument, as in JS), toUpperCase, toLowerCase, trim, trimStart, trimEnd, split (with a limit), repeat, charAt, at, charCodeAt, codePointAt, concat, padStart, padEnd, replace, replaceAll, match, matchAll, search; String.fromCharCode(...codes), String.fromCodePoint(...). Positions count characters (code points), not UTF-16 code units: charCodeAt returns a code point, and -1 outside the string (NaN in JS).

#Regular expressions

const LINE = /^(\S+) \[([^\]]+)\] "(\w+) (\S+)"$/;
const m = line.match(LINE);                   // string[] | null: [match, group1, ...]
if (m !== null) console.log(m[3], m[4]);
/^\d+$/.test("2026");                          // true
"a1b22".replace(/\d+/g, "#");                  // "a#b#"
"x=1, y=2".replace(/(\w)=(\d)/g, (all, k, v) => `${k}:${v}`);
"2026-09-29".replace(/(?<y>\d+)-(?<m>\d+)-(?<d>\d+)/, "$<d>.$<m>.$<y>");
"a, b ,c".split(/\s*,\s*/);                    // ["a", "b", "c"]
for (const [all, key, value] of "k1=v1;k2=v2".matchAll(/(\w+)=(\w+)/g)) { ... }
new RegExp(`^${prefix}`, "i");                  // a pattern from a string
  • /.../flags literals with the flags g, i, m, s, u, d are checked at compile time. A RegExp is data, { source, flags }: a regular expression can be sent in a message, and it has the fields source and flags.
  • Methods: re.test(s), re.exec(s); on strings, match, matchAll (needs g), search, replace, replaceAll (needs g), split. The semantics are those of JS: match with g returns all matches, split includes the separator's groups, and empty matches are handled the same way. A group that did not take part in the match is "" (undefined in JS). A replacement function receives the match and the groups (up to seven).
  • Matching time is linear in the length of the string for any pattern: catastrophic backtracking cannot happen. That is why two JS features that need backtracking are missing: lookahead and lookbehind ((?=...), (?<=...)) and backreferences (\1); the compiler reports them. \d, \w and \b are ASCII, as in JS; \p{L} works with the u flag.

#Maps and sets

Map<K, V> and Set<T> are immutable: the methods that mutate in JavaScript return a new collection. The old version stays as it was, and the versions share the common parts of their structure (HAMT), so a copy is cheap.

const m = new Map<string, int>().set("a", 1).set("b", 2);
const m2 = m.set("a", 10).delete("b");     // m is unchanged
m2.get("a");                               // 10 (type int | null)
m2.has("b");                               // false
m.size;                                    // 2

const counts = new Map([["x", 1], ["y", 2]]);   // types are inferred: Map<string, int>
for (const [k, v] of counts) console.log(k, v);
counts.forEach((v, k) => console.log(k, v));
counts.keys(); counts.values(); counts.entries();

const s = new Set([3, 1, 2]).add(4);
s.has(2);                                  // true
s.union(new Set([10])); s.intersection(t); s.difference(t); s.symmetricDifference(t);
s.isSubsetOf(t); s.isSupersetOf(t); s.isDisjointFrom(t);
[...s];                                    // an array of the elements
  • Keys are compared structurally: records, tuples and arrays work as keys (Map<Point, string>).
  • Iteration order is insertion order, as in JavaScript. A new value for an existing key does not move the key; a key that is deleted and added again goes to the end. union appends new elements at the end; intersection and difference keep the order of the left set. Equality === does not depend on order.
  • While there is only one reference to a map, set/delete change it in place (a flat hash table, as in JS). If the old version is still needed, it stays intact: the map is copied or switches to a persistent tree, where an update copies only the path to the entry.
  • new Map() with no arguments has the type Map<never, never> and "grows" with set. With an annotation, const m: Map<string, int> = new Map(), the type comes from the annotation.
  • If the result of m.set(...), s.add(...) or xs.with(...) is not used, the compiler warns: out of JS habit, it is easy to "mutate" and lose the result.

#Binary data

The typed arrays Uint8Array, Int8Array, Uint16Array, Int16Array, Uint32Array, Int32Array, Float32Array and Float64Array store numbers of one kind contiguously, as in JavaScript: pixels, vertices, bytes of files and packets. Elements of integer arrays read as int; elements of Float32Array and Float64Array read as float.

const px = new Float32Array(4 * n);                // n sprites: x, y, vx, vy
const u = new Uint8Array([1, 2, 300]);             // [1, 2, 44]: integers wrap around, as in JS
const f = Float64Array.from(xs, (x) => x * 2.0);   // from an array of numbers or another typed array
const g = Int16Array.of(1, 2, ...rest);
px.length; px[0]; px.at(-1);                       // at → float | null
const moved = px.with(0, 1.5).with(1, 2.5);        // a new array; in place if there is one reference
px.fill(0.0, 4, 8); px.set(other, 16);             // also new arrays
px.copyWithin(0, 4, 8);                            // elements 4..8 moved to 0..4, also a new array
px.subarray(4, 8);                                 // a view of the same buffer, no copying
px.slice(4, 8);                                    // a copy
px.map((x, i) => x * 2.0); px.filter((x) => x > 0.0); px.reduce((acc: float, x) => acc + x, 0.0);
for (const b of u) console.log(b);
[...u];                                            // int[]
const bytes = new TextEncoder().encode("hello");   // Uint8Array, UTF-8
new TextDecoder().decode(bytes);                   // "hello"
new TextDecoder("utf-8", { fatal: true });         // invalid UTF-8 crashes the process instead of giving U+FFFD
  • Typed arrays are immutable, like everything in XQ: with, fill, set, copyWithin, map, filter, sort and reverse return a new array, and JavaScript's t[i] = v is written as t.with(i, v). If there is only one reference to the array, the update happens in place: step(p.with(i, x).with(i + 1, y), i + 2) in tail recursion works like a loop with assignment, and map writes into the same array. The indices and values in a with chain are evaluated before the first update, so reading the old array in them (p.with(i, p[i] + p[i + 2] * dt)) does not stop the update from happening in place.
  • The elements live in a buffer outside the process heap, with its own atomic reference count. A message or a new process gets one more reference to the same buffer: megabytes of data are passed without copying. While the buffer is visible to anyone else, a change goes to a copy, so no process sees another process's changes. A crashed process releases its references to buffers.
  • Integer elements are stored modulo their width, and Float32Array rounds to f32, as in JavaScript. Single values (with, fill, of) for integer arrays must be int; the constructor, from and set convert fractional numbers as JS does (they drop the fractional part; NaN and infinities become 0).
  • === compares elements. JSON.stringify writes an array of numbers (in JS, an object with index keys), and console.log prints Float32Array(2) [1.5, 2.0]. sort() orders the numbers (NaN last); sort with a comparator works as for arrays. includes finds NaN and indexOf does not, as in JS. A type check in match: t: Uint8Array => ....
  • Bytes in files and sockets: fs.readBytes(path) → Result<Uint8Array>, fs.writeBytes, fs.appendBytes, net.readBytes(s) (an empty array means the connection is closed), net.writeBytes(s, bytes). To turn a value into bytes and back, use Binary (see Binary messages).
  • ArrayBuffer, DataView, BigInt64Array and Uint8ClampedArray are not supported yet.

#Performance of immutable code

If a value has no other references, an "immutable" update is done in place: nothing is copied, and the semantics stay the same. That is why accumulating in tail recursion is fast:

function build(n: int, acc: int[]): int[] {
  if (n == 0) return acc;
  return build(n - 1, [...acc, n]);        // amortized O(1): nothing else sees acc
}

function tick(s: State, n: int): State {
  if (n == 0) return s;
  return tick({ ...s, count: s.count + 1 }, n - 1);   // the record is updated in place
}

This works for [...xs, x], xs.append, xs.concat, xs.with, { ...r, f: v }, m.set, m.delete, s.add, and for strings: acc + x and `${acc}...` append to the end of acc in place, so building a string piece by piece is linear. If the old value is still in use, a copy is made, and the old value does not change.

The same holds for collections inside records and arrays. { ...state, items: [...state.items, x] } appends to the state's array in place if the old state is no longer needed (a Redux-style reducer takes O(1) per action). The same goes for a collection field passed to a function: { ...t, grid: scroll(t.grid, n) } takes t.grid out of the record, and scroll updates the grid's arrays in place. A field first read into a variable (const g = t.grid) remains a second reference to the same data, and an update through it copies the data: write t.grid in the update itself. xs.map((p) => ({ ...p, x: p.x + 1 })) over an array that is no longer needed updates the records in place, with no new allocations.

Slices do not copy long arrays: xs.slice(1) and the rest in the pattern [h, ...t] refer to the elements of the original array, so recursion over an array is linear, like recursion over a list in Erlang. A short slice is copied so that it does not keep a large array in memory. stack.slice(0, -1) on an array with no other references shortens it in place: an immutable stack built on [...s, x] and s.slice(0, -1) takes O(1) per operation.

Strings are stored in UTF-8, and length, charAt, slice and indexOf count characters as in JS (outside the BMP they count code points, not UTF-16 surrogate pairs). A pass over a string with any characters, Cyrillic included, is linear: the runtime remembers positions in long strings.

A const f = line.split(" ") that is then read only as f[i] and f.length does not build an array of all the pieces: strings are created only for the fields that are read. Parsing a log line of twenty fields, six of which are needed, costs six strings, not twenty. If the array goes anywhere else (it is passed to a function, iterated over or captured by a closure), this is an ordinary split.

Array methods that take a lambda (map, filter, reduce, forEach, some, every, find, findIndex) compile to a plain loop: the lambda's body is inlined, and no closure is created. A pipeline such as range(0, n).map(...).filter(...).reduce(...) becomes a single loop with no intermediate arrays if the callbacks do nothing but compute a value (no console.log, send, I/O, now, Math.random). Callbacks with effects run step by step, in the same order as in JS.

Such a pipeline over a long input (1024 elements or more) may run in parallel if the callbacks are pure and do not call self(). The runtime first computes the last few elements itself and parallelizes the rest only if the work is worth it. The result is the same as that of a plain loop, including the order of elements and the crash message. reduce is split only if regrouping the operations cannot change the result: an integer accumulator with acc + e, Math.max or Math.min.

A loop over an array of numbers, an array of records with numeric fields or a typed array, where each step writes only its own element (ps.map((p) => step(p, dt)), recursion with w.pos.with(2 * i, x)), is split across cores without copying: the threads write straight into the shared buffer. A step may read any elements of arrays that the loop does not write, and call small functions, which are inlined. A step that prints, sends, builds strings or arrays, or calls a function that was not inlined runs in order, and so do a float sum and a step that reads an element another step writes. Setting the environment variable XQ_PAR=0 turns parallelism off.

#Unions, narrowing, match

type Shape =
  | { kind: "circle"; r: float }
  | { kind: "rect"; w: float; h: float };

function area(s: Shape): float {
  return match (s) {
    { kind: "circle", r } => Math.PI * r * r,
    { kind: "rect", w, h } => w * h,
  };
}

function describe(s: Shape): string {
  if (s.kind === "circle") return `circle ${s.r}`;   // s is narrowed to circle
  return `rect ${s.w}x${s.h}`;                        // and here to rect
}

function len(s: string | null): int {
  if (s === null) return 0;
  return s.length;
}

Patterns in match/receive:

PatternExample
literal0, "ok", true, null

record (partial){ kind: "circle", r }, { pos: { x, y } }, { by: amount }

If no clause matches, the process crashes (no matching clause). The compiler warns about a non-exhaustive match:

warning: `match` is not exhaustive: `{ a: float, kind: "tri" }` not covered

#Processes

A process is a function that runs concurrently. Its mailbox is typed by the pseudo-parameter this: Process<M>:

type Req = { type: "add"; n: int } | { type: "get"; replyTo: Pid<int> };

function acc(this: Process<Req>, total: int): void {
  receive {
    { type: "add", n } => acc(total + n),
    { type: "get", replyTo } => {
      replyTo.send(total);
      acc(total);
    },
    after 5000 => console.log("idle, exiting"),
  }
}

function main(this: Process<int>): void {
  const pid = spawn(acc, 0);                // Pid<Req>
  pid.send({ type: "add", n: 5 });          // or send(pid, msg)
  pid.send({ type: "get", replyTo: self() });
  receive {
    total => console.log(total),
  }
}
  • spawn(f, args...): the arguments are evaluated in the parent and copied into the new process. spawn<M>(() => ...) spawns a process from an arrow function.
  • self() is the process's own Pid<M>. send checks the message type against M.
  • receive takes the first message in the mailbox that matches one of its clauses; the others wait their turn. after ms => ... fires if no matching message arrives for ms milliseconds (after 0 means "just check").
  • sleep(ms) pauses without reading messages. now() is the number of milliseconds since the program started, and performance.now() is the same with fractions of a millisecond (float), for measuring short intervals. For the date, use os.time(): milliseconds since 1970 by the system clock (the clock can be set forward or back, so durations are measured with performance.now()).
  • Messages are copied: processes have no shared memory.
  • Broadcast: send(pids, msg) or pids.send(msg) for an array Pid<M>[] sends one message to all of them. This is faster than a loop: the message is built once, receivers are woken in batches, and more than a few thousand receivers are split between threads (to 100,000 processes it is twice as fast as a send loop). Processes that have exited are skipped; the order of messages from one sender to each receiver is preserved.
  • A function that does receive requires the same this: Process<M> in its caller. This guarantees that only messages of the expected type arrive in the mailbox.

#Priorities

A process that cannot wait (a game frame, sound, input) is spawned with high priority, and background work with low priority:

const render = spawn({ priority: "high" }, renderLoop, world);
const loader = spawnLink({ priority: "low" }, loadAssets, paths);
const was = setPriority("high"); // sets this process's own priority; returns the previous one
  • A priority, of the built-in type Priority, is "low", "normal" (the default) or "high". A spawned process has normal priority unless told otherwise; the helper threads of parallel loops run at the priority of the process that started them.
  • A ready high process goes ahead of all others. If no thread is free, a thread running a lower-priority process yields to it at its next check, within microseconds rather than at the end of a time slice. Under full load, a frame process gets its message in under 0.1 ms.
  • A low process runs when no normal process is waiting to run, and also on every eighth turn of a thread, so that it makes progress under load too.
  • High priority is for work that does not come too often and cannot wait. A normal process takes a stream of messages in batches, while a high-priority one wakes up for every message, which costs more.

#Calls, names, stopping

A request that expects a reply is pid.call: a function builds the request from the pid the reply should come to, and the call waits for the reply:

type Req = { type: "add"; n: int } | { type: "get"; reply: Pid<int> };

const r = counter.call((reply) => ({ type: "get", reply }), 1000); // Result<int>
if (r.ok) console.log(r.value);
else console.log(r.error); // "timeout", "noproc", or the reason the server exited with
  • The reply type comes from the server's message type: the field the function puts the pid into (in the request with the same type) is Pid<T>, so the reply is T. If it cannot be determined this way, write it on the parameter: (reply: Pid<int>) => ....
  • The timeout is in milliseconds, 5000 by default; a negative timeout waits for as long as the server is alive. If the server exits before replying, the call returns at once with an error that carries the server's exit reason.
  • The reply goes not to the caller's mailbox but to the pid of this call: the mailbox type does not have to include the reply type, and a reply that comes after the timeout is lost. A call costs 0.5 µs (a send and receive pair costs 0.3 µs).

A process gets its name when it is spawned; whereis finds a process by name:

spawn({ name: "counter" }, counter, 0);
const c = whereis<Req>("counter"); // Pid<Req> | null
if (c !== null) c.send({ type: "add", n: 1 });
  • A name is taken while its process is alive: spawning a second process with the same name is an error. Once the process has exited, the name is free.
  • whereis<M> checks that the process was spawned with the same message type M; otherwise it is an error that crashes the calling process: a pid found by name cannot be used with a message type other than its own. whereis<never> finds a process of any type.

To stop another process: pid.kill() stops it at once, whatever it is doing (the reason is killed, and trapping exits does not help); pid.kill(reason) sends an exit signal, as from a crashed linked process: a process that traps exits receives Exit, any other process exits with reason ("normal" leaves it running). kill does not wait: the process exits on its own thread; to wait for it, use monitor.

#Errors and supervision

"Let it crash": an error (integer overflow, division by zero, an out-of-bounds index, badmatch, panic(msg), a process stack overflow) terminates only that process and prints a report to stderr.

type Sup = Down | Exit | { type: "done"; v: int };

function main(this: Process<Sup>): void {
  const w = spawn(worker, self());
  monitor(w);               // when w exits, { type: "DOWN", pid, reason } arrives
  trapExit(true);           // signals from linked processes become messages { type: "EXIT", ... }
  const l = spawnLink(() => panic("boom"));
  receive {
    { type: "DOWN", pid, reason } => console.log("worker down:", reason),
    { type: "EXIT", pid, reason } => console.log("linked exit:", reason),
    { type: "done", v } => console.log(v),
  }
}
  • link(pid) / spawnLink(...) create a two-way link: an abnormal exit of one process terminates the other (unless the other calls trapExit(true)).
  • monitor(pid) sets up one-way monitoring: a Down message arrives.
  • exit(reason) ends the current process with a reason ("normal" is a normal exit).
  • Down and Exit are built-in types; monitor/trapExit require them to be part of the mailbox type.

The supervisor from the standard library starts processes and restarts the ones that crash:

import * as supervisor from "std/supervisor";

const sup = supervisor.start({
  strategy: "oneForOne", // "oneForAll": all of them; "restForOne": the crashed one and those started after it
  intensity: 3, // more than 3 restarts
  period: 5000, // within 5 seconds, and the supervisor gives up
  children: [
    { id: "db", start: () => spawnLink({ name: "db" }, database) },
    { id: "web", start: () => spawnLink(webServer, 8080), restart: "transient" },
  ],
});
const kids = supervisor.children(sup); // [{ id, pid }]; pid is null if the child is not running
supervisor.stop(sup); // the children exit in reverse order, then the supervisor itself
  • start starts the children in order and returns once all of them are running. The supervisor is linked to the process that started it: when that process exits, the supervisor stops the children and exits with the same reason. A supervision tree is a supervisor among the children of another one: start: () => supervisor.start({ ... }).
  • restart: permanent (the default) means always restart, transient means restart only after a failure (a reason other than normal or shutdown), temporary means never (the child leaves the list).
  • A child is stopped with the exit signal shutdown: a child that traps exits receives Exit and can finish its work, but after shutdown ms (5000 by default; 0 means at once) it is killed.
  • After more than intensity restarts within period ms (3 within 5000 by default), the supervisor stops all its children and crashes with too many restarts. The process that started it crashes too, unless it traps exits.
  • A child gets its name in start (spawnLink({ name }, f)): after a restart the name belongs to the new process, and clients find it with whereis. To name the supervisor itself, use the name field of its spec.
  • supervisor.startChild(sup, { id, start, restart }) adds a child to a running supervisor (for example, the process of a chat when the chat is first opened) and returns its Pid, or null if the supervisor is gone.

#I/O and the standard library

The standard library is imported with an ordinary import from the std/... modules. Errors are values of type Result<T> = { ok: true; value: T } | { ok: false; error: string }, not exceptions:

import { readFile, writeFile, appendFile, exists, remove, mkdir, readDir } from "std/fs";
import { readLine, readAll, write, writeErr } from "std/io";

Networking (TCP):

const l = net.listen("127.0.0.1", 8080);          // Result<Listener>; port 0 picks any free port
if (!l.ok) return;
const a = net.accept(l.value);                    // Result<Socket>
if (a.ok) {
  const s = a.value;
  const h = spawn(() => serve(s));                // one process per connection
  net.handOver(s, h);                             // the socket is closed when h exits
}
// in serve: net.readLine(s) → Result<string | null>, net.read(s), net.write(s, text), net.close(s)

TLS: net.listenTls(host, port, { cert, key }) accepts encrypted connections (the certificate and the key are PEM files), and net.connectTls(host, port) opens them. The server's certificate must match host and be signed by a certificate authority from the Mozilla root certificates (built into the program) or from a file: net.connectTls(host, port, { ca: "ca.pem" }). After that it is an ordinary socket: read, write, close, handOver. net.connect(host, port, { from: "127.0.0.2" }) (and connectTls with the same from) connects from that address of this machine: bots on the same machine as the server can open more connections to it than one address has ports for (on Linux the port is chosen when the connection is made, IP_BIND_ADDRESS_NO_PORT).

Binary data is read and written as Uint8Array (Binary data): fs.readBytes, fs.writeBytes, fs.appendBytes, net.readBytes, net.writeBytes.

An open file is for a log that is appended to and read in pages from any position:

const f = fs.open("chat.log", "append");      // Result<fs.File>; "read" (the default) is read-only
if (!f.ok) return;
const at = fs.append(f.value, bytes);         // Result<int>: the byte offset where the record starts
const page = fs.readAt(f.value, 0, 4096);     // Result<Uint8Array>: up to 4096 bytes from byte 0 (fewer at the end)
const n = fs.size(f.value);                   // Result<int>
fs.close(f.value);

The file belongs to the process that opened it and is closed when that process exits. The offset that append returns is the end of the file before the write: it is correct if no one else writes to the file at the same time. fs.truncate(path, size) keeps the first size bytes of a file: for example, it cuts off a log record that a machine failure left unfinished.

  • Operations that have to wait (reading stdin, files and sockets, accept, connect) suspend only the calling process; the scheduler keeps working. Sockets run on an event loop: thousands of connections occupy no threads, and a line that has already arrived is read without a thread switch. Files and stdin are read on a separate thread pool.
  • net.read returns whole characters: a multi-byte UTF-8 character split at a packet boundary waits for the rest of its bytes. Connections are opened with TCP_NODELAY: a reply goes out immediately, as in Go and Node.
  • A socket belongs to the process that opened or accepted it and is closed when that process exits (including when it crashes). To pass a socket to another process, use net.handOver(socket, pid).
  • net.localPort(listener) is the port of a listening socket; net.localHost(socket) is the IP address the connection arrived at (IPv4 as is, not mapped to IPv6), which is how a server learns where its clients find it; net.peerHost(socket) is the peer's address (a server counts its clients by it).
  • net.lookup(name) returns the IP addresses of a name (DNS, the hosts file; an address resolves to itself), IPv4 first: Result<string[]>.
  • The standard library modules are written in XQ on top of declare function: declarations of functions implemented in the runtime.

#Frames (TCP)

import * as net from "std/net";

type Msg = net.Frame | { type: "say"; text: string }; // the client's frames and messages from other processes

function session(this: Process<Msg>, s: net.Socket): void {
  net.frames(s); // the frames of s come to this process as messages
  serve(s);
}

function serve(this: Process<Msg>, s: net.Socket): void {
  receive {
    { type: "frame", data } => {
      net.sendFrame(s, data); // goes out when the process yields its thread
      serve(s);
    },
    { type: "say", text } => {
      net.sendFrame(s, Binary.encode<string>(text));
      serve(s);
    },
    { type: "closed", error } => {}, // the client left (error is null) or the connection broke
    after 60000 => net.close(s), // silent for a minute
  }
}
  • A frame is a length (unsigned LEB128) followed by that many bytes. net.frames(s, { max, queue }) switches a socket, plain or TLS, to frame mode: frames come to the process that called frames as net.Frame messages, { type: "frame", socket, data }, and the last message is { type: "closed", socket, error }. The mailbox type must include net.Frame, just as it must include net.Datagram for UDP. The connection's process waits in a single receive both for the client and for messages from other processes: no second process is needed for reading.
  • The owner reads the socket only when it has nothing else to take from its mailbox: a busy process does not read, TCP slows the client down, and the mailbox does not grow. A frame longer than max (16 MB by default) closes the connection, and the reason is in closed.
  • net.sendFrame(s, data) does not wait for the network: frames accumulate in the socket's queue and go out when the process yields its thread (it waits for a message or its time slice runs out), everything it sent in the meantime in a single system call. Any process that has the socket can send. A queue longer than queue (1 MB by default: the client is not reading) closes the connection.
  • net.sendFrames(sockets, data) puts one frame into the queues of many sockets: this is how a channel process writes a message to all its subscribers at once without waking the processes of their connections. More than a few hundred sockets are split between threads, and the frames go out to the network immediately. It returns how many sockets the frame was put into (closed ones are skipped).
  • net.read and net.write on a socket in frame mode are an error; net.handOver(s, pid) hands over the frames too.
  • WebSocket is frame mode too: net.frames(s, { webSocket: "server" }) (or "client") after the handshake (which http.acceptWebSocket and http.connectWebSocket perform, see HTTP). A frame is one WebSocket message, binary or text, assembled from its fragments; net.sendFrame and net.sendFrames send binary ones. The server accepts only masked frames, and the client masks its own. The runtime answers a ping by itself and a close with a close, and net.close sends one. An unmasked frame from a client, a control frame longer than 125 bytes or a message longer than max closes the connection with code 1002 or 1009, and the reason comes in closed. This way one and the same process serves both a TCP client and a browser: the server sends both the same bytes, and sendFrames writes each socket its own header.
  • An idle connection costs the service about 8 KB of memory (process, socket, buffers, without TLS): a million connections fit in 8 GB.

#Datagrams (UDP)

import * as net from "std/net";

type Msg = net.Datagram | { type: "tick" };

function echo(this: Process<Msg>, s: net.Udp): void {
  receive {
    { type: "datagram", host, port, data } => {
      net.sendTo(s, host, port, data); // reply to the sender
      echo(s);
    },
    { type: "tick" } => echo(s),
  }
}

function main(this: Process<Msg>): void {
  const s = net.openUdp("0.0.0.0", 7777); // Result<Udp>; port 0 picks any free port, "::" takes IPv6 and IPv4
  if (s.ok) echo(s.value);
}
  • The socket belongs to the process that opened it: every datagram that arrives comes to it as a net.Datagram message, { type: "datagram", udp, host, port, data }, as in Erlang (gen_udp in active mode). So the owner's mailbox type must include net.Datagram; otherwise openUdp is a compile error. The owner takes datagrams in the same receive as its other messages: a server that distributes datagrams to rooms also hears from the rooms themselves.
  • The sender's address consists of ordinary values, host (the IP address as a string) and port: they can be stored, compared and used as a key in a Map. data is a Uint8Array outside the process heap.
  • The process takes datagrams that arrived back to back as a batch, without locking the mailbox for each one. While 16,384 datagrams (or 4 MB) are waiting for the owner, further ones are dropped, as UDP drops them.
  • sendTo(s, host, port, data) sends one datagram; any process that has the socket can send, so rooms send snapshots to their players themselves. host is an IP address (a name is looked up on every call). sendMany(s, [{ host, port, data }, ...]) sends many at once, on Linux with one system call per 64 (sendmmsg); one that fails does not stop the others, and the error is that of the first failed one.
  • The same data to many, such as voice to a room: const to = net.destinations([{ host, port }, ...]) parses the addresses once (Result<Destinations>, IP addresses only), and net.sendAll(s, to.value, data, except) sends data to every address in the list except the one at index except (-1 sends to all): one buffer for all, on Linux 64 per system call, and a long list in parts on other threads at once. net.count(to) is the number of addresses in the list.
  • udpPort(s) is the socket's port, closeUdp(s) closes it, and handOverUdp(s, pid) transfers ownership: datagrams that the owner has not taken yet go to the new owner too. The socket is closed when its owner exits.
  • IPv6: "::1", "::". A socket on "::" accepts IPv4 too, and an IPv4 sender appears as "127.0.0.1", not "::ffff:127.0.0.1"; such a socket can also send to IPv4 addresses.

#Sound (std/audio)

Capture from a microphone and playback, with 16-bit samples. A device belongs to the process that opened it, like a socket, and is closed along with it. Captured sound comes to the owner as messages, frame by frame, in the same receive as its other messages, and any process that has the device can play sound:

import * as audio from "std/audio";

type Msg = audio.Captured | { type: "stop" };

function echo(this: Process<Msg>): void {
  const mic = audio.openInput({ rate: 48000, channels: 1, frame: 960 });   // 20 ms frames
  const out = audio.openOutput();
  if (mic.ok && out.ok) loop(mic.value, out.value);
}

function loop(this: Process<Msg>, mic: audio.Input, out: audio.Output): void {
  receive {
    { type: "captured", samples } => {
      audio.play(out, samples);                      // what is said is what you hear
      loop(mic, out);
    },
    { type: "stop" } => audio.closeInput(mic),
  }
}
  • audio.openInput(options) → Result<Input>, audio.openOutput(options) → Result<Output>; options is { device?, rate?, channels?, frame?, voice? }, by default 48,000 samples per second, one channel, a frame of 960 samples. The mailbox type of the input's owner includes audio.Captured: { type: "captured"; input; samples: Int16Array; time }, with the channels' samples interleaved; time is when the frame's first sample was captured (µs, on the performance.now clock): the system holds sound in its buffer, and the frame arrives a few milliseconds later. Frames that wait for the owner longer than a second are dropped, oldest first.
  • voice: true means call sound: the system's communications device, and the system processes the stream as a call. On Windows it removes the echo of what is playing from what is captured and suppresses noise where it can; audio.effects(i) tells what it does to the input ("echo cancellation", "noise suppression", "gain control", ...; Windows 11). The sound of other programs is not lowered, although the system would lower it in a call.
  • audio.play(o, samples) queues sound after what is already waiting (at most two seconds of sound waits); audio.queued(o) is how many samples per channel have not been played yet, in the queue and in the system's buffer: a program that plays sound as it arrives keeps a few tens of milliseconds there. audio.underruns(o) is how many times the output ran out of sound after it started playing: each time is a gap that a person heard (the program was late topping up the sound). closeInput and closeOutput close the devices.
  • Devices: "default" is the system's device (on Windows, WASAPI in shared mode: the system converts the rate and the channels itself). Devices without sound exist on every system and run at the pace of a real one (tests, bots): with "null" an input gives silence and an output plays to nowhere; "tone:440" is an input that gives a sine wave of that frequency; with "file:path" an input gives the sound of a WAV file (16-bit, with the same rate and number of channels) and then silence, and an output writes what it played to such a file, with silence where there was nothing to play, which is what a person would have heard. Linux and macOS have no system sound devices yet, only these.

#Camera (std/video)

A camera belongs to the process that opened it, like a microphone, and is closed along with it; pictures come to the owner as messages, in the same receive as its other messages. A picture is I420: one luma byte per pixel, row by row, then two chroma planes (blue, red) at half the width and height, which is what video codecs take:

import * as video from "std/video";

type Msg = video.Frame | { type: "stop" };

function watch(this: Process<Msg>): void {
  const cam = video.open({ device: "default", width: 640, height: 360, fps: 30 });
  if (cam.ok) loop(cam.value);
}

function loop(this: Process<Msg>, cam: video.Camera): void {
  receive {
    { type: "videoFrame", width, height, time, data } => {
      // data: width × height luma bytes, then chroma; time is when it was taken, µs on the performance.now clock
      loop(cam);
    },
    { type: "stop" } => video.close(cam),
  }
}
  • video.open(options) → Result<Camera>; options is { device?, width?, height?, fps? }, by default 640 × 360 at 30 frames per second (width and height are even). Camera is { camera, width, height, fps }: what the camera actually delivers. The owner's mailbox type includes video.Frame: { type: "videoFrame"; camera; width; height; time; data: Uint8Array }. A picture that is still waiting for the owner when two newer ones have arrived is dropped: a late picture is worth less than the next one.
  • Cameras: "default" is the system's first camera, or a name from video.cameras(); the system converts pictures to I420 and scales them to the requested size (on Windows, Media Foundation; its libraries are loaded when a camera is opened for the first time). Cameras without a device exist on every system and run at the pace of a real one (tests, bots): "test" gives a moving image of color bars, a square that goes around the frame in two seconds, and the frame number in 16 black-and-white squares at the top left, which video.stamp(luma, width, stride?) reads back, even after a codec; "test:ms" is the same image, but each picture is handed over that many milliseconds after it was taken, as a real camera hands it over (tests of synchronization with sound); "file:path" plays the frames of a Y4M file (YUV4MPEG2, 4:2:0) in a loop, at its size and frame rate. Linux and macOS have no system cameras yet, only these.
  • video.frameBytes(width, height) is the number of bytes in an I420 picture; video.close(cam) closes the camera.

#Cryptography (std/crypto)

Random bytes, SHA-256, HMAC-SHA256, AES-GCM and Ed25519 signatures, from the same library that TLS uses (ring), for a program's own protocols: signing a message so that the server knows whose it is, sealing sound so that only those who have the key can hear it, or making an account that is itself a key.

import * as crypto from "std/crypto";

const key = crypto.randomBytes(16);                  // an AES-128 key (32 bytes for AES-256)
const sealed = crypto.seal(key, nonce, header, data); // ciphertext and a 16-byte tag that also covers header
const data2 = crypto.open(key, nonce, header, sealed);  // Uint8Array | null: null for another key, nonce or header
const tag = crypto.hmac(secret, bytes);              // 32 bytes
crypto.verify(secret, bytes, tag.slice(0, 16));      // the tag or its start (16+ bytes), compared in constant time
const digest = crypto.sha256(bytes);                 // 32 bytes
const seed = crypto.randomBytes(32);                 // the secret of an Ed25519 key
const key = crypto.publicKey(seed);                  // the public key, 32 bytes: safe to show
const sig = crypto.sign(seed, bytes);                // a signature, 64 bytes
crypto.verifySignature(key, bytes, sig);             // true: signed by the owner of seed
  • nonce is 12 bytes, and it must never repeat with the same key: usually a message number and a sender number.
  • A key of the wrong length or a nonce that is not 12 bytes is a program error, and the process crashes; someone else's or corrupted data gives null from open and false from verify and verifySignature.
  • Ed25519 keys and signatures are the same as WebCrypto's in the browser (importKey("pkcs8", ...) from the same seed): a browser client signs the same way as an XQ program.

#WebRTC (std/rtc)

The WebRTC transport for a media server: what a browser needs from a server to send it sound and video and to receive them from it. The browser checks the path with STUN requests (ICE; the server is ICE-lite and only answers), agrees on keys over DTLS 1.2, trusting the server's certificate by its fingerprint from SDP, and then sends RTP and RTCP sealed with SRTP: AEAD_AES_128_GCM, or AES_CM_128_HMAC_SHA1_80, which every WebRTC implementation has. The packets themselves (RTP, RTCP, SDP) are up to the program; this module is the cryptography.

import * as net from "std/net";
import * as rtc from "std/rtc";

rtc.fingerprint();                             // "sha-256 AB:CD:...": the program's certificate fingerprint for SDP
rtc.kind(data);                                // "stun" | "dtls" | "rtp" | "rtcp" | "other", by the first byte
const user = rtc.stunUser(data);               // "server ufrag:browser ufrag" | null
const answer = rtc.stunAnswer(data, pwd, host, port);  // an answer with the sender's address | null (wrong password)

const d = rtc.dtls("server", fingerprintFromOffer);   // an association of this process
rtc.input(d, data).forEach((x) => net.sendTo(udp, host, port, x));   // handshake: what to send in reply
if (rtc.state(d) === "connected") {
  const packet = rtc.unprotect(d, srtp);       // the browser's RTP | null
  net.sendTo(udp, host, port, rtc.protect(d, rtp) ?? new Uint8Array(0));
}
  • An association (Dtls) and the SRTP of both directions, whose keys it produced, belong to the process that created it and go away with that process (or with rtc.close). The program has a single certificate (ECDSA P-256, self-signed), made when it is first needed.
  • The server is the passive side of DTLS: it requests the browser's certificate, checks its fingerprint against SDP and verifies signatures made with its key (ECDSA P-256, RSA). The cipher suite is TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256 with the extended master secret; the server sends its flight again when the browser has repeated its own. The client side is for tests: rtc.start(d) gives the first flight, rtc.retransmit(d) a retransmission when there is no answer; it understands the server's cookie (HelloVerifyRequest).
  • SRTP profile: rtc.dtls(role, fingerprint, profiles) accepts only the listed ones ("AEAD_AES_128_GCM", "AES_CM_128_HMAC_SHA1_80"; without them, both, and the server prefers AES-GCM); rtc.profile(d) is the one agreed on.
  • protect, unprotect, protectRtcp, unprotectRtcp are SRTP and SRTCP (RFC 3711, RFC 7714): before the handshake completes and for foreign packets they return null. rtc.exported(d) is the SRTP keying material (for tests: it is the same on both sides).
  • rtc.stunRequest(user, pwd, controlling) and rtc.stunAnswered(data, pwd) are the browser's side, for tests.

#Running programs (std/exec)

import * as exec from "std/exec";

const r = exec.run("git", ["log", "--oneline", "-5"]); // Result<{ code, stdout, stderr }>
if (r.ok) console.log(r.value.code, r.value.stdout);

const c = exec.start("python", ["-u", "worker.py"], { cwd: "tools", env: new Map([["MODE", "fast"]]) });
if (!c.ok) return;
const p = c.value; // { child, pid, stdin, stdout, stderr }
exec.write(p.stdin, "task 1\n");
const answer = exec.readLine(p.stdout); // Result<string | null>
exec.close(p.stdin); // the program reads its input to the end
const code = exec.wait(p); // Result<int>
  • start(program, args, options) starts a program: a path to it or a name that is looked up in PATH (on Windows with .exe added; a .cmd or .bat script is written with its extension: npm.cmd). Arguments arrive as they are, without a shell. run starts a program and waits for it to end: the exit code, the whole output and the whole error output; its input is empty. A windowed program (xq build --gui) starts console programs without a console window.
  • Options: cwd; env, variables added to this program's environment (with clearEnv: true, used instead of it); stdin, stdout, stderr: "pipe" (the default: a pipe to this program), "inherit" (this program's streams) or "null"; stderr: "stdout" sends errors to the same place as the output.
  • pty: { cols, rows } runs the program in a pseudoterminal: it sees a terminal (colors, line editing, full-screen programs), stdin and stdout are the terminal itself, errors go there too, and the stream options have no effect. Keys are written to the input the way a terminal sends them (Enter is "\r"); a new size is set with exec.resize(c, cols, rows), and the program learns about it. On Windows this is ConPTY (Windows 10 1809 and later): it redraws the screen itself, so the output is not the program's bytes but sequences that draw the same thing. If conpty.dll and OpenConsole.exe lie next to the executable (Windows Terminal and VS Code carry their own copy of ConPTY the same way), that ConPTY is used: it passes the program's output through as is and is six times faster, but it queries the terminal, for its attributes (ESC [ c) at the start and for the cursor position (ESC [ 6n) after a resize, and waits for the answer, so the program that reads the output must answer like a terminal.
  • Reading works as with sockets: read (what has arrived, in whole characters; "" at the end), readLine (null at the end), readBytes (Uint8Array, without copying; empty at the end). Writing: write, writeBytes; close closes a stream. wait returns the exit code (on Linux, a program killed by signal n gives 128 + n); kill kills the program at once.
  • A program belongs to the process that started it: when that process exits, the program is killed; to pass it to another process, use exec.handOver(c, pid). Programs that are still running when the XQ program as a whole exits are killed too.
  • Waiting for output, for room in the input or for the program to end suspends only the calling process. The output is read by a runtime thread of its own while the program writes (up to 4 MB ahead), so the program does not wait for its output to be read.

#Windows and graphics (std/gpu)

import * as gpu from "std/gpu";

function main(this: Process<gpu.Event>): void {
  const w = gpu.window({ title: "demo", width: 800, height: 600 }); // Result<Window>
  if (!w.ok) panic(w.error); // an error where there is no display or GPU
  // Rectangles, 8 numbers each: x, y, width, height, r, g, b, a.
  loop(w.value, new Float32Array([100.0, 100.0, 200.0, 50.0, 1.0, 0.5, 0.0, 1.0]));
}

function loop(this: Process<gpu.Event>, w: gpu.Window, rs: Float32Array): void {
  receive {
    { type: "frame", dt } => {          // the window is ready for the next frame
      gpu.present(w, gpu.frame([gpu.pass(gpu.screen, gpu.rgb(0.1, 0.1, 0.12), [gpu.rects(rs)])]));
      loop(w, rs);
    },
    { type: "key", key: "Escape", down: true } => {}, // the process exits, and the window closes
    { type: "closed" } => {},
    _ => loop(w, rs),
  }
}
  • The process that opens a window is its owner: the window's events come to it as messages, mixed in with messages from other processes, and its mailbox type must include gpu.Event (like Down for monitor). The window closes when the owner exits or calls gpu.close(w). When the user closes the window, the owner only gets the message closed; the program decides what to do.
  • Events: frame (the window is ready for the next frame; dt is the time in seconds since the previous frame, n is the frame number), resize (width, height in screen pixels; scale is the screen's scale), key (key is the key's name: "a", "Enter", "ArrowLeft"; code is its position on the keyboard regardless of layout: "KeyA", "Digit1", like KeyboardEvent.code on the web; down; mods holds the bits gpu.SHIFT, gpu.CTRL, gpu.ALT, gpu.META), text (what a key press typed), pointer (x, y; buttons holds a bit per pressed button: 1 left, 2 right, 4 middle), wheel (dx, dy in scroll lines), focus (focused), closed.
  • gpu.setTitle(w, title) changes the window title. The system clipboard, as text: gpu.clipboard() → Result<string>, gpu.setClipboard(text) → Result<null>; on Linux it works through xclip, xsel or (under Wayland) wl-clipboard, if one of them is installed. The calling process is suspended while it waits.
  • A frame is a value. gpu.frame(passes) is a list of passes. A pass, gpu.pass(target, clear, items), draws its items in order into the window (gpu.screen) or into a texture, after clearing the target to the color clear (gpu.rgb, gpu.rgba; with null, it draws over what the target already holds). Passes run in order: an item may use a texture that earlier passes drew into, but not the target of its own pass. The runtime derives the command order, barriers and image layouts. Items are many instances in one Float32Array, with one draw call per item, or text:
    • gpu.rects(xs) draws rectangles, 8 numbers each: x, y, width, height (in pixels of the target, y down), r, g, b, a (from 0 to 1; a blends the color with what is underneath);
    • gpu.sprites(t, xs) draws sprites of texture t, 13 numbers each: x, y, width, height, u0, v0, u1, v1 (which part of the texture, from 0 to 1; u1 < u0 mirrors it), angle (radians, clockwise around the center), r, g, b, a (what the texture's color is multiplied by);
    • gpu.lines(xs) draws segments with round ends, 9 numbers each: x0, y0, x1, y1, thickness, r, g, b, a; a line thinner than a pixel is drawn one pixel wide and fainter;
    • gpu.roundRects(xs) draws rectangles with rounded corners and a border inside, 14 numbers each: x, y, width, height, corner radius, border thickness, r, g, b, a of the fill, r, g, b, a of the border;
    • gpu.ellipses(xs) draws ellipses (circles when the width equals the height) with a border, 13 numbers each: x, y, width, height of the rectangle that the ellipse fills, border thickness, r, g, b, a of the fill, r, g, b, a of the border;
    • gpu.polyline(points, width, color) draws a polyline through the points (2 numbers each: x, y) of thickness width, with rounded joins and ends, in one call; where a translucent polyline meets itself, the colors add up;
    • single shapes: gpu.rect(x, y, w, h, color), gpu.roundRect(x, y, w, h, radius, fill, border?, edge?), gpu.circle(x, y, radius, fill, border?, edge?), gpu.line(x0, y0, x1, y1, width, color), gpu.image(t, x, y, width, height) (the whole texture in a rectangle). Each is a record with numbers in its fields, with no array of its own; consecutive shapes of the same kind are drawn in one call, like an array;
    • gpu.clip(x, y, width, height, items) draws items only inside the rectangle (on whole pixels) and inside the clip of the enclosing group, if there is one; groups nest (up to 256 deep);
    • gpu.draw(m, data, textures?) draws instances of the custom material m in one call: m.floats numbers per instance and up to four textures that its shader reads (see below);
    • gpu.text(font, s, x, y, size, color, align?) draws text in font font, size pixels high (the em size, up to 1024): left to right, \n starts a new line, a tab is four spaces, with the font's kerning. x, y is the top left corner of the first line; with align set to "center" or "right", it marks the middle or the right edge that each line is aligned to. Baselines fall on whole pixels, letters on quarter pixels.

Shape edges are antialiased over one pixel. Consecutive items of the same kind and the same texture are drawn in one call, and a long list of items is recorded on all cores: the process that submits the frame records its items in chunks together with the helper threads (a clip group is recorded as one chunk). A large array is not copied on the process's thread: the frame holds a reference to the array's buffer until the GPU thread copies the numbers into a buffer for the GPU. The array can be changed right away; while the reference is held, a change copies the array, and by the next frame the reference is already released, so the array changes in place.

  • gpu.present(w, frame) shows a frame in the window; only the owner may present. The window sends frame when it is ready for the next frame, like requestAnimationFrame but as a message; the display's refresh rate sets the pace. A frame presented early waits until the window is ready: the process is suspended, but the scheduler thread is not. At most two frames are in flight.
  • Images: gpu.decodeImage(bytes) → Result<Image> decodes a PNG (of any kind: grayscale, palette, 16-bit) into { width, height, pixels }, where pixels is a Uint8Array with 4 bytes (r, g, b, a) per pixel and rows from top to bottom. The decoding runs in the I/O thread pool; the calling process is suspended while it waits. An Image can also be built by hand.
  • Textures: gpu.texture(img) makes a texture from an image, gpu.texture({ width, height }) an empty (transparent) one. { smooth: false } as the second argument samples the nearest texel (pixel art); otherwise four texels are blended. { format: "r8" } stores one byte per pixel, which a shader reads as red (a video plane; an image's pixels are then one byte each), and passes do not draw into such a texture. The texture is returned at once, its pixels go to the GPU in the background, and a frame that draws the texture finds them there. gpu.write(t, pixels, stride?) gives a texture new pixels: rows of stride bytes (by default, as many as a row of the texture takes; a decoder's frame has longer rows, and the excess is skipped). The process does not wait; frames submitted after the call draw the new pixels, frames submitted before it draw the previous ones. If there is no GPU or no GPU memory left, the process crashes (gpu.device() → Result<string>, the device name, tells whether there is a GPU). A texture belongs to the process that created it and is freed when that process exits or calls gpu.release(t); frames that already use it still finish drawing. gpu.handOver(t, pid) transfers ownership. Any process that the texture has been sent to can use it. gpu.render(frame) draws a frame into textures without a window (a process has at most two such frames in flight; a third waits for the GPU), and gpu.read(t) returns the pixels (as in Image); the calling process is suspended while it waits for the GPU.
  • Fonts: gpu.font(bytes) → Result<Font> reads a TrueType or OpenType font (from a collection, the first font) in the I/O thread pool; the calling process is suspended while it waits. A font belongs to a process, like a texture: gpu.release(f), gpu.handOver(f, pid). gpu.measure(font, s, size) → { width, height, ascent } gives the width of the longest line, the height of the lines and the distance from the top to the baseline of the first line, as gpu.text lays them out; it needs no GPU. Glyphs are rasterized on the CPU the first time a frame draws them at that size (by the helper threads that record the frame) and stay in an atlas on the GPU while the program runs. Ligatures, scripts whose letters join or reorder (Arabic, Indic), right-to-left text and word wrapping are not supported yet.
  • Custom materials: gpu.material(wgsl, { blend? }) → Result<Material> compiles a WGSL shader in the I/O thread pool; the calling process is suspended while it waits, and a compile error is reported as text with the line and column in the shader. A material draws one quad per instance. The vertex function vs gets the vertex index (@builtin(vertex_index), from 0 to 3) and the instance's numbers: its @location(n) inputs (f32 and vectors of f32) read the item's array in location order, and Material.floats is how many numbers an instance takes. A material without inputs draws one instance per item: a pass over the whole target, such as post-processing. The fragment function fs colors the quad. The shader can call gpu_size() (the target's size in pixels), gpu_position(p) (a point in pixels, y down, as the position that vs returns), gpu_corner(i) (a corner of the quad: (0, 0), (1, 0), (0, 1), (1, 1)), gpu_sample(n, uv) (the item's texture n, through its filter), gpu_texel(n, p) and gpu_texture_size(n). blend is "alpha" (over the target by opacity, like the built-in items), "add" (added to it) or "replace" (in its place). A texture that an earlier pass drew in the same frame is an ordinary input of the next pass:

ts const blur = gpu.material(BLUR, { blend: "replace" }); // Result<Material> gpu.present(w, gpu.frame([ gpu.pass(scene, gpu.rgb(0.0, 0.0, 0.0), [gpu.sprites(t, xs)]), gpu.pass(gpu.screen, null, [gpu.draw(blur.value, Float32Array.of(1.0, 0.0), [scene])]), ]));

A material belongs to a process, like a texture: gpu.release(m), gpu.handOver(m, pid); frames hold it until the GPU has drawn them. The shader compiler is included only in programs that call gpu.material.

  • The GPU does a process's work in the order of its calls: gpu.read after gpu.present or gpu.render sees what they drew. An error in a frame (a released texture, font or material; a texture in its own pass; a text size out of range; an array of the wrong length; another process's window or a closed one; gpu.screen in gpu.render) crashes the process with a reason.
  • While windows are open, waiting for their events is not a deadlock.
  • A program that imports std/gpu is built with the runtime that has graphics; programs without the import are built without graphics. Vulkan is loaded at startup: without a GPU the program still runs, and gpu.window and gpu.device return an error.
  • Environment variables: XQ_GPU_DEBUG=1 turns on the Vulkan validation layers if they are installed (synchronization validation also needs VK_KHRONOS_VALIDATION_VALIDATE_SYNC=true); XQ_GPU_DEVICE=Intel picks the GPU whose name contains that string; XQ_GPU_HIDDEN=1 makes windows invisible (for tests); XQ_GPU_ATLAS=n sets the side of a glyph atlas page in pixels (2048 by default; the atlas test uses 64).

Examples: examples/sprites.xq: 100,000 sprites, with the frame rebuilt on every frame; examples/text.xq: text in different sizes in Russian and English, alignment, and labels that change every frame; examples/chart.xq: a live chart in a panel with clipping, a grid, labels and a cursor; examples/glow.xq: glowing particles, post-processing with custom materials. Benchmarks cover frame recording on multiple cores, 10,000 changing labels, a chart of 100,000 points with 10,000 rectangles, a custom material against the built-in one and the glow, stutter under load, a scene crash, and a comparison with raylib.

#HTTP

std/http is an HTTP/1.1 server and client, over plain text or TLS (https):

import * as http from "std/http";

function handler(req: http.Request): http.Response {
  if (req.path == "/hello") return http.text(`hello, ${req.query}`);
  if (req.path == "/echo" && req.method == "POST") return http.bytes(req.body);
  if (req.path == "/user") return http.json(JSON.stringify({ id: 1, name: "Ann" }));
  return http.status(404);
}

function main(): void {
  const s = http.listen({ port: 8080 });   // + cert, key for HTTPS; port: 0 for any free port
  if (s.ok) http.serve(s.value, handler);  // does not return
}

function post(url: string): void {          // client
  const r = http.fetch(url, { method: "POST", headers: [["x-tag", "1"]], body: "text" });
  if (r.ok) console.log(r.value.status, r.value.headers.get("content-type"), http.bodyText(r.value.body));
  else console.log(r.error);
}
  • Request: method, path (without the query), query (after the ?, without it), headers (Map<string, string>: names in lower case, repeated headers joined with ", "), body (Uint8Array), keepAlive. Response: status, headers ([string, string][]), body (string | Uint8Array); it is built with http.text, html, json, bytes, status. content-length, date and a default content-type are added automatically.
  • Each connection is served by its own process: a slow client does not hold up the others, and a crashed handler closes only its own connection. Keep-alive, pipelined requests, chunked bodies, Expect: 100-continue and HTTP/1.0 are supported. To a bad request the server itself responds with 400, 413 (a body over 256 MB), 431 (headers over 64 KB) or 501.
  • The handler is an ordinary function without a mailbox. If a connection needs to wait for messages (for example, a reply from a storage process), write the connection loop yourself with http.readRequest(socket) → Request | null and http.respond(socket, req, res); see the example examples/http_server.xq.
  • http.fetch(url, { method, headers, body, ca }) → Result<ClientResponse> (status, headers, body). Only the calling process waits. Each request opens its own connection; redirects are not followed, and there is no timeout yet.
  • WebSocket: http.isWebSocket(req) tells whether a request asks to open a WebSocket; http.acceptWebSocket(s, req, { max, queue }) responds with 101 Switching Protocols (400 to a request that is not a WebSocket upgrade, 426 to another protocol version) and switches the socket to WebSocket frame mode: messages come to the calling process as net.Frame, and its mailbox type must include them. http.connectWebSocket(url, { max, queue, ca, headers }) is the client: ws:// or wss://, the key and its check per RFC 6455; headers are request headers in addition to its own.

#JSON

JSON.parse<T>(text) parses text directly into a value of type T and returns Result<T>:

type User = { id: int; name: string; email: string | null; tags: string[] };

const r = JSON.parse<User[]>(text);
if (!r.ok) {
  console.log(r.error);   // JSON.parse: $[3].tags[0]: expected a string, found a number (line 1, column 212)
  return;
}
for (const u of r.value) console.log(u.name, u.tags.length);
console.log(JSON.stringify(r.value));           // back to text
console.log(JSON.stringify(r.value, null, 2));  // indented
  • T is built from null, bool, int, float, string, literal types, records, arrays, tuples, Map<string, V>, Set<T> and unions. Extra keys of an object are skipped; a field may be missing if its type includes null. int accepts only integers, float any number.
  • A union picks its member by the kind of value, and record members by their fields, for example by a literal discriminant: { kind: "circle"; r: float } | { kind: "rect"; w: float; h: float }.
  • Without a type argument, JSON.parse(text) gives Result<Json>, where Json = null | bool | int | float | string | Json[] | Map<string, Json> is a built-in type; its values are taken apart with match and type tests (m: Map<string, Json> => ..., xs: Json[] => ...). The type can also come from an annotation: const r: Result<Config> = JSON.parse(text).
  • JSON.stringify(value) writes records (fields in the order of the type's declaration), arrays, maps (keys are strings or integers) and sets (as arrays); numbers and string escaping are as in JavaScript. JSON.stringify(value, null, indent) writes with indentation (a number of spaces or a string).
  • Differences from JS: the result of JSON.parse is checked against the type (in TS, JSON.parse(text) as T checks nothing); int and float are distinct; a Map is written as an object (in JS, as {}), a typed array as an array of numbers (in JS, as an object with indices); JSON.parse does not build typed arrays: parse a float[] and convert it with new Float32Array(xs).

#Binary messages

Binary.encode(value) writes a value in a compact binary form that follows its type, and Binary.decode<T>(bytes) reads it back and returns Result<T>. They are meant for network messages, snapshots and files:

type Entity = { id: int; kind: "ship" | "rock"; x: float; y: float; owner: int | null };

const bytes = Binary.encode(entities);              // Uint8Array
const r = Binary.decode<Entity[]>(bytes);
if (!r.ok) console.log(r.error);                    // tag 7 is not of the 2 members of the union (at byte 30)
  • The bytes hold no names and no types, only values: the type says what comes next. An int is a variable-length integer (zigzag and LEB128: −64 to 63 takes one byte), a float is eight bytes (little-endian), a bool is one byte, a string is its length in bytes followed by UTF-8; an array, a Set and a Map are the number of elements followed by the elements (for a map, key and value alternate, in insertion order); a tuple is its elements; a record is its fields in the order of their names; a union value is a tag (the member's number) followed by the member; a typed array is its length followed by its bytes as they are. null and literal types take no bytes at all.
  • The order is set by the type itself, not by how it is written: fields go by name, union members by the canonical text of their types. Programs built separately with the same types read each other's data, whatever their aliases are called and in whatever order the members are listed.
  • T is built from null, bool, int, float, string, literal types, records, tuples, arrays, Set, Map, typed arrays and unions, including recursive ones (type List = { head: string; tail: List } | null). The type must be known where Binary is called: a type parameter is a compile error. Binary.decode(bytes) without a type argument takes the type from the expected Result<T>.
  • Binary.encode(value) writes a value by its static type, Binary.encode<T>(value) as a value of type T. The type of a literal is more precise than it seems: for { type: "hit", by: 1 } it is { by: int; type: "hit" }, not the union of messages, and the string "hit" takes no bytes at all. So a message literal is written with its type, Binary.encode<Event>({ type: "hit", by: 1 }), and the compiler warns about literal types and null outside unions and aliases in the argument's type.
  • The encoder identifies a union member by the kind of value and the shape of the record, and records of the same shape by the fields in which they differ: { type: "hit"; by: int } | { type: "heal"; by: int } by type.
  • decode accepts anything. Data that is truncated or has extra bytes, a tag or a length that cannot occur, a bool other than 0 or 1, an integer longer than 64 bits or a string that is not UTF-8 gives an error with the byte position, not a crash and not a read out of bounds. A length is checked against the remaining bytes before anything is allocated, so a corrupted length does not ask for gigabytes. Recursive types nest as deep as the process stack allows: deeper nesting is an error in decode and a process crash in encode.
  • The compiler generates dedicated encode and decode functions for each type: a snapshot of 1,000 objects is encoded in 3.6 µs and decoded in 9.9 µs, while hand-written Go code with encoding/binary takes 4.7 and 19.9 µs.
  • Binary.schema<T>() is the binary form of a type described in JSON (a string that the compiler builds ahead of time), for programs in other languages: "int", "float", "bool", "string", "null", {"literal": v}, {"record": [[name, T], ...]} (fields in their order), {"tuple": [...]}, {"array": T}, {"set": T}, {"map": [K, V]}, {"typed": "u8"}, {"union": [...]} (members in tag order) and a recursive alias {"alias": n, "type": T} with references {"ref": n} inside. A program in another language — a web client in TypeScript, say — reads and writes the messages of an XQ server with it, tag for tag, without a copy of the protocol that would need editing for every new member, and generates their types from the same schema.

#Databases (std/pg, std/redis)

Clients of PostgreSQL and Redis are built into the runtime: the protocols are its own, on its sockets, without libpq or hiredis. A client's connections are shared by all processes of the program. A process waits for the server as it waits for any socket, and the scheduler thread runs other processes meanwhile.

import * as pg from "std/pg";
import * as redis from "std/redis";

type User = { id: int; name: string; age: int | null };

function main(): void {
  const d = pg.connect("postgres://app:secret@localhost:5432/shop");   // ?sslmode=require etc.
  const k = redis.connect("redis://localhost:6379");                   // rediss:// for TLS
  if (!d.ok || !k.ok) return;
  const db = d.value;
  const users = pg.query<User>(db, "SELECT id, name, age FROM users WHERE age > $1", [30]);
  if (users.ok) for (const u of users.value) console.log(u.name, u.age ?? "?");
  pg.exec(db, "UPDATE users SET age = age + 1 WHERE id = $1", [7]);

  const c = k.value;
  redis.set(c, "user:7", "Ann", { ex: 60 });
  console.log(redis.get(c, "user:7"));                                // { ok: true, value: "Ann" }
  console.log(redis.command(c, ["HINCRBY", "stats", "visits", 1]));   // any command
}

PostgreSQL:

  • pg.connect(url, { size, ca }) → Result<Db>. The address is postgres://user:password@host:5432/db with the parameters sslmode=disable|prefer|require|verify-ca|verify-full (default prefer: TLS if the server takes it), application_name, options; the password goes as SCRAM-SHA-256, md5 or plain text, as the server asks. A Db is a pool of connections: a query takes a connection for its time, and size is how many there are at most (default: ten for each scheduler thread, opened as they are needed). One opens at once, to check the address and the password.
  • pg.query<T>(db, sql, params) → Result<T[]> gives the rows as T directly: a record takes the columns of its fields' names (others are left out), a tuple takes them in order, Map<string, V> takes all of them, and a number or a string takes the first one. A column becomes an int (smallint … bigint, numeric without a fraction), a float, a bool, a string (any type, as the server writes it: timestamp, numeric, uuid…), a Uint8Array (bytea), a Json or any type a JSON text can be (json, jsonb); NULL goes only into a type with null. A mismatch is an error that names the column: column `qty` is null where an integer was expected. pg.queryOne<T> → the first row or null. As with JSON.parse<T>, the type must be known where it is called.
  • The parameters $1, $2… are pg.Value: null, bool, numbers, strings, Uint8Array (bytea), arrays and maps (JSON, for json and jsonb). The server parses a query once on each connection (a prepared statement), and numbers and bool go in binary.
  • pg.exec(db, sql, params) → Result<int>: how many rows it affected; without parameters, sql may be several statements separated by ;.
  • pg.transaction<R>(db, (tx) => ..., begin) runs the function on a connection given to it alone: ok means COMMIT, anything else ROLLBACK; begin may be, for example, "BEGIN ISOLATION LEVEL SERIALIZABLE". A process that crashes or is killed in the middle of a transaction leaves its connection closed, and the server rolls it back.
  • pg.listen(db, channels): NOTIFY notifications come to the calling process as pg.Notification messages ({ type: "pg"; channel; payload; pid }), so its mailbox type must include them; pg.unlisten(l) stops them.
  • A server error comes with its SQLSTATE code: syntax error at or near "SELEC" (42601).

Redis:

  • redis.connect(url, { size, ca }) → Result<Client>; the address is redis://[user:password@]host[:port][/db], rediss:// for TLS. RESP3 with servers that speak it (Redis 6 and later), RESP2 with older ones.
  • The commands of all processes go out on two shared connections. Commands sent at the same time go to the server in one write and come back together, as a pipeline would, without a pipeline in the program: 64 processes reading a key make 690 thousand commands a second on Linux, go-redis with a pool of 64 connections 244 thousand. A command that blocks its connection (BLPOP, BRPOP, BLMOVE, BZPOPMIN, WAIT, XREAD … BLOCK…) takes a connection of a pool for its time; size is how many there are at most (default: ten for each scheduler thread). A command that would change a shared connection (SELECT, AUTH, MULTI, WATCH, SUBSCRIBE, CLIENT REPLY…) is an error: the database goes in the address, and for the rest there are transaction and subscribe.
  • redis.command(c, args) → Result<redis.Reply> runs any command; its arguments are strings, numbers and Uint8Arrays. The reply is an XQ value: null, bool, int, float, a string (bytes that are not UTF-8 come as a Uint8Array), an array, a Map<string, Reply>; an error reply is a Result with the error. Ready wrappers: get, getBytes, set ({ ex, px, nx, xx }), mget, del, exists, incr, expire, ttl, hget, hset, hgetAll, hdel, lpush, rpush, lpop, rpop, lrange, llen, sadd, srem, smembers, sismember, publish, ping.
  • redis.pipeline(c, commands) sends commands at once and returns their replies in order (an error reply of one of them is { error } in its place); redis.transaction(c, commands) does the same inside MULTI … EXEC: no other client's command runs between them.
  • redis.subscribe(c, channels) and redis.psubscribe(c, patterns): messages come to the calling process as redis.Message ({ type: "redis"; channel; message; pattern }) on a connection of their own, which closes with redis.unsubscribe(s) or when the process ends.

#Calling C functions

declare library declares functions of a dynamic C library. The library is loaded on the first call:

import * as ffi from "std/ffi";

declare library "sqlite3", "winsqlite3" {      // the names are tried in order
  function sqlite3_libversion(): string;
  function sqlite3_open(filename: string, out db: Pointer | null): i32;
  function sqlite3_errmsg(db: Pointer): string;
  blocking function sqlite3_step(stmt: Pointer): i32;    // runs on the I/O pool
  export function sqlite3_column_text(stmt: Pointer, column: i32): string | null;   // visible to importers
}

declare library "m" {
  function frexp(x: f64, out exp: i32): f64;
}

declare library "c" {
  function memset(inout dst: Uint8Array, c: i32, n: usize): Pointer;
  function qsort(inout base: Float64Array, n: usize, size: usize, compare: (a: Pointer, b: Pointer) => i32): void;
}

function main(): void {
  console.log(sqlite3_libversion());
  const [rc, db] = sqlite3_open(":memory:");             // the result, then the out parameters
  const [m, e] = frexp(48.0);                            // 0.75, 6
  const [_, bytes] = memset(new Uint8Array(8), 7, 4);    // [7, 7, 7, 7, 0, 0, 0, 0]
  const xs = qsort(new Float64Array([3.0, 1.0, 2.0]), 3, 8, (a, b) =>
    ffi.readF64(a, 0) < ffi.readF64(b, 0) ? -1 : 1);     // [1, 2, 3]: C calls an XQ function
}
  • C types: i8, i16, i32, i64, u8, u16, u32, u64, isize, usize (int in XQ); f32, f64 (float); bool; void (result only); Pointer, an address in C memory; string, a null-terminated UTF-8 C string (an argument is copied for the duration of the call, a result is copied into an XQ string); a typed array is a pointer to its elements. Only Pointer | null and string | null admit null: it is the null address. If a function returns NULL where string is declared, the calling process crashes.
  • Integer arguments are converted to the width of the type, as in C. A u64 greater than 2⁶³−1 reads as a negative number.
  • out p: T: the function writes a value (a number, bool or Pointer) at the address p, and no argument is passed for it. inout a: Uint8Array: the function writes into a typed array; an array that is also visible elsewhere is copied first, so immutability is not broken. The call returns a tuple: the result, then the out values and the new inout arrays in parameter order. A void result is left out of the tuple, and a single value is returned without a tuple.
  • Library names: "c" and "m" are the C library (ucrtbase.dll on Windows, libc.so.6 and libm.so.6 on Linux). On Windows, name.dll and libname.dll are searched for; on Linux, libname.so and libname.so.0 ... libname.so.9. A path or a name with an extension is used as is.
  • A missing library, or a function missing from the library, crashes the calling process. ffi.loads(name) tells whether a library is available (it searches the same way as declare library): a program can do without an optional library. A client, say, runs without noise suppression when rnnoise.dll is not next to it.
  • std/ffi reads memory returned by a C function: ffi.readCString(p), ffi.readBytes(p, n) → Uint8Array, ffi.readI8 ... ffi.readF64(p, offset), ffi.readPointer(p, offset), ffi.offset(p, n), ffi.address(p), ffi.pointer(n) (for constants like SQLITE_TRANSIENT = ffi.pointer(-1)). Reading at the null address crashes the process; reading at an invalid address crashes the whole program, as in C.
  • C functions are values, like other functions (xs.map(abs)). A call costs 7–17 ns and runs on the scheduler thread: while the function runs, other processes wait for that thread.
  • blocking function is for functions that wait for a disk, the network or a lock, or compute for long. The call runs on a thread of the I/O pool: the process waits for it as for a file read, and the scheduler thread runs other processes meanwhile. Such a call costs about 1 µs. Typed arrays are passed as they are: the process is not torn down until the call returns, even when killed (it ends right after). While 24 processes write to an SQLite database, a high-priority process wakes on time: on Linux 99 % of its delays are under 0.2 ms, against 18–60 ms without blocking.
  • The calls of one process come from different system threads, the ordinary ones (processes move between scheduler threads) and blocking ones alike. What a function leaves in its thread (errno, GetLastError) the next call may not see. A library that needs all its calls from one thread needs a C wrapper with a thread of its own.
  • A parameter of a function type is a pointer to a C function: the call is passed an XQ function (or null, if the type admits it), and C calls it during the call, in the process that called C. Its parameters and result are C types, as for library functions, but no typed arrays, string results or other functions; at most eight parameters. The function runs on a stack of its own and can do anything ordinary code does: call C, send messages, wait (receive, sleep, files). If it crashes, or the process is killed while it waits, C gets 0 from that call and the following ones, and the process ends when C returns. A call costs 30–45 ns; while the function waits, the scheduler thread waits with it, as it is inside the C call.
  • In a blocking function, C calls the XQ function on the pool's thread, which hands the call to the process: the process runs it while it waits for the C call, as its own code, and when it waits, the scheduler thread runs other processes. Such a call costs about 1 µs: fine for the rows of sqlite3_exec, not for comparing millions of elements.
  • C may call an XQ function only during the call it was passed to, and only on that call's thread: a call later or from another thread ends the program with a message saying so.
  • struct Name { field: type; ... } in declare library is a C struct: its fields in memory order, of C number types, bool, Pointer and other structs, laid out as C lays them out. In XQ its value is a record of these fields, and its name is the record's type (const v: Vector2 = { x: 1.0, y: 2.0 }). A struct parameter or result is passed by value as the platform's calling convention wants (Windows x64, System V x86-64, AArch64); with out p: Vector2 the function fills a struct through a pointer, with inout it changes the one passed, and both come back as new records. XQ functions called from C take and return no structs: a Pointer instead.

ts declare library "raylib" { struct Vector2 { x: f32; y: f32 } struct Color { r: u8; g: u8; b: u8; a: u8 } function GetMousePosition(): Vector2; function DrawCircleV(center: Vector2, radius: f32, color: Color): void; }

  • There are no variadic functions (printf), arrays in structs or reading a struct at a pointer a function returned yet. A complete example is examples/sqlite.xq.
